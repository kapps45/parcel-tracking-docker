# 🐳 Parcel Tracking — Docker

Контейнеризация Go-сервиса для управления данными о посылках с использованием **SQLite**.

Проект показывает, как упаковать Go-приложение в Docker-образ с помощью многоэтапной сборки и подготовить минимальный runtime-образ для запуска приложения.

## 🔧 Что реализовано

- 🏗️ Сборка Go-приложения внутри Docker
- 🔄 Многоэтапная сборка Docker-образа
- ⚙️ Отдельный этап для компиляции приложения
- 🪶 Минимальный runtime-образ на базе Alpine
- 📥 Автоматическая загрузка Go-зависимостей
- 🚀 Запуск готового бинарного файла внутри контейнера
- 🗃️ Использование SQLite для хранения данных о посылках

## 📦 Структура проекта

| Файл | Назначение |
|---|---|
| `main.go` | Точка входа и запуск приложения |
| `parcel.go` | Работа с данными посылок и SQLite |
| `parcel_test.go` | Тесты операций с хранилищем |
| `Dockerfile` | Многоэтапная сборка Docker-образа |
| `go.mod` | Описание Go-модуля и зависимостей |
| `go.sum` | Контрольные суммы зависимостей |
| `tracker.db` | Файл базы данных SQLite |

## 🐳 Docker-сборка

В `Dockerfile` используется **multi-stage build**:

1. На этапе `builder` устанавливаются зависимости и компилируется Go-приложение.
2. На финальный этап переносится только готовый бинарный файл.
3. Приложение запускается в отдельном минимальном Alpine-образе.

Такой подход позволяет не переносить инструменты сборки и исходный код в итоговый runtime-образ.

## 🚀 Запуск без Docker

Для локального запуска выполните:

    go run .

Запуск тестов:

    go test ./...

## 🐳 Сборка Docker-образа

Собрать Docker-образ:

    docker build -t parcel-tracking-service .

Запустить контейнер:

    docker run --rm parcel-tracking-service

Если требуется использовать собственный тег:

    docker build -t <docker-id>/parcel-tracking-service:v1 .

## 🎯 Цель проекта

Практика контейнеризации Go-приложений: создание Dockerfile, использование многоэтапной сборки, уменьшение состава финального образа и запуск приложения в изолированной среде.
